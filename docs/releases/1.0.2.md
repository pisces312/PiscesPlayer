# PiscesPlayer 1.0.2 — Music Quiz / 猜歌挑战

**Hear a 10-second clip from your own library and guess the song: ten rounds, five titles, one answer each. Plus a music games hub and a song picker for the rhythm game.**

**听 10 秒本地歌曲片段猜歌名：10 题一局、5 选 1、每题只答一次。同时新增音乐游戏大厅与节奏游戏选歌页。**

PiscesPlayer is a fork of [PixelPlayerOSS](https://github.com/PixelPlayerHQ/PixelPlayerOSS) (GPL-3.0-or-later, by @lostf1sh). 1.0.2 keeps the same package name (`com.pisces312.piscesplayer`) and signing key as 1.0.0 and 1.0.1, so it installs over them directly. It still cannot be installed over an upstream PixelPlayerOSS or F-Droid build; moving a library between them uses the in-app backup and restore.

## English

### 1. Music Quiz — your library, ten rounds

Reach it from the home screen's game button, then open the Music Quiz card in the games hub.

- **The rules are fixed so high scores stay comparable**: 10 rounds per run, a 10-second clip, and a 10-second window to answer. The clip starts at a random position inside the song rather than always at the beginning, and the correct song never repeats within a run. Each round can only be answered once — repeated taps do not score twice.
- **Five plausible titles, not an obvious giveaway**: distractors are matched to the answer by title language, release decade and genre, then the five options are shuffled. Titles that look identical after whitespace/case normalisation are never shown together. If the library cannot supply a close match, the game falls back to other songs so a round always works.
- **Speed-based scoring**: a correct answer earns 100–1000 points depending on the time left; a wrong answer or a timeout earns 0, with no penalty. A full run can reach 10000 points. Only a completed run updates the best score and best streak — leaving mid-run discards it, and the pause dialog says so before you confirm.
- **No spoilers**: quiz clips play on their own player, isolated from the main player. The mini player is hidden, and the clip is never published as a media session title or notification. Cover art, artist and the full title appear only after you answer, when the correct option is highlighted in green and a wrong pick in red. Correct answers advance automatically after a short delay; wrong answers and timeouts wait for you to tap Next.
- **Results you can act on**: score, accuracy, longest streak, average answer time, new-record badges and a per-round review. Tapping a review row previews that song in full with the quiz's own player (your main queue and listening stats are untouched), and you can select review songs to create a playlist — the default name includes a timestamp. Play again re-rolls the whole run; Back to games returns to the hub.
- **Clear prerequisites**: at least 10 playable local songs with a title, a duration of 30 seconds or more and a readable local URI, plus 5 distinct titles. The setup screen shows the reason and the current count instead of failing after the game starts. Broken or undecodable files found while playing are replaced at runtime.

Everything above is local: no account, no network request, no cloud track.

### 2. Music games hub and song picker

- A single games hub now collects both games; the home screen's game button opens it.
- Before starting the rhythm game you can pick a song from a dedicated picker with three filters: recently played songs, difficulty, and songs that already have a saved chart. The picker reads only chart catalogue metadata — it does not parse chart JSON or touch the database.
- The existing rhythm setup screen is unchanged; the picker only decides which song it opens with.

### 3. Housekeeping

- Removed unused Wear OS artwork configuration and 20 dead hardcoded changelog string-arrays (English and Simplified Chinese); the in-app changelog has long read the repository CHANGELOG.md at runtime.
- Fixed wording that implied crash data was uploaded. Crash capture is entirely local: the log is copied to the clipboard or shared by the user, never sent anywhere.
- Removed stale alpha / stable / F-Droid / channel keywords from settings search, and corrected the README badge and unsigned-build instructions that still assumed prerelease and F-Droid channels.

## 中文

### 1. 猜歌挑战 —— 用你自己的曲库，10 题一局

入口：首页右上角的游戏按钮 → 音乐游戏大厅 → 猜歌挑战卡片。

- **规则固定，最高分才有可比性**：每局 10 题，试听 10 秒，答题窗口也是 10 秒。片段从歌曲有效范围内的随机位置开始，而不是总从开头播；同一局内正确的歌不会重复。每题只能作答一次，连续点击不会重复计分。
- **5 个选项要像真的**：干扰项按「歌名语种 → 发行年代 → 流派」的优先级匹配，再统一打乱；大小写/空白归一化后显示相同的歌名不会同时出现。曲库里同语种歌曲不足时会降级跨语种补足，保证题目始终出得来。
- **答得越快分越高**：答对得 100–1000 分，答错或超时 0 分、不倒扣；一局理论满分 10000。只有完整打完一局才更新最高分与最佳连对；中途退出不保存本局成绩，暂停确认框会先说明这一点。
- **全程防剧透**：试听走猜歌游戏自己的播放器，与主播放器隔离；迷你播放条隐藏，片段不会作为媒体会话标题或通知暴露。封面、歌手和完整歌名只在作答后揭晓——正确项标绿、选错标红。答对约 1.2 秒后自动进入下一题，答错或超时停留在揭晓页等你点「下一题」。
- **结算页可继续操作**：总分、正确率、最长连对、答对平均用时、破纪录提示与逐题回顾。点回顾行可用猜歌自己的播放器整曲试听（不替换主队列、不计入听歌统计）；也可勾选回顾歌曲生成歌单，默认名带时间戳。「再玩一次」用新随机种子重开一局，「返回大厅」回到游戏列表。
- **开局条件写清楚**：至少 10 首可播放的本地歌曲（标题非空、时长 ≥ 30 秒、有可读取的本地 URI），且至少 5 个不同歌名。准备页直接显示原因与当前数量，不会进答题页后才报错；播放时才发现损坏或无法解码的文件会在运行时替换。

以上全部基于本地曲库：不需要账号、不发网络请求、不涉及云端曲目。

### 2. 音乐游戏大厅与选歌页

- 两个游戏统一收进一个大厅，首页右上角的游戏按钮直达。
- 节奏游戏开始前新增独立选歌页，提供三个筛选器：最近播放、难度、已有谱面。选歌只读谱面目录元数据，不解析谱面 JSON、不改数据库。
- 原有节奏游戏设置页不变，选歌页只决定用哪首歌打开它。

### 3. 维护清理

- 删除未使用的 Wear OS 封面配置，以及 20 个硬编码的 changelog 死资源（中英文各一组）；应用内更新日志早已改为运行时读取仓库 CHANGELOG.md。
- 修正「崩溃上报系统」这类误导文案：崩溃日志完全本地，只复制到剪贴板或由用户主动分享，不会上传到任何地方。
- 移除设置搜索里已失效的 alpha / stable / F-Droid / channel 关键词，并修正 README 徽章与未签名构建说明中仍假设预发布和 F-Droid 通道的措辞。
