# 旋律选音对比：原声对齐为什么"没有旋律"（2026-11-03）

问题：ONSET（原声对齐）派生的谱面旋律线基本消失。用户假设"按音量强度筛选、
阈值按曲子自适应"应当能保住旋律。本实验在 6 首验证曲上量化机制并对比改进方向。
工具：`experiments/melody_select.py`（Python 镜像 `RhythmChartDeriver.deriveOnsetNative`）。

## 机制诊断（为什么旋律消失）

1. `onsetStrength` = novelty **瞬态通量峰高**（`RhythmChartGenerator.kt:156`），
   不是音量：军鼓/kick 的瞬态比人声字头强数倍，此尺度下打击天然碾压旋律。
2. 选音是在 **min-gap + 每秒密度预算**下按 (0.05+strength)×拍上加权竞争
   （加权区间调度 + 1 s 窗口准入）。旋律音符头弱、数量多，撞上更强打击就被裁。
3. 旋律是**序列**：成对存活率（相邻旋律 onset ≤500 ms 且双双保留）在 EASY 只有
   2.1%、NORMAL 14.3%——线被切成孤点，听感即"没有旋律"。
4. 响度/密度约束（`minRmsPercentile`/`maxLocalNps`）默认关闭，与本问题无关；
   问题在排序特征与预算，不在阈值大小。

指标口径：voice 类按 onset 主频带（8 对数频带 21 Hz–22 kHz）：LOW=band0–1（底鼓/低频）、
MELODY=band2–5（108 Hz–2.4 kHz，人声/贝斯/主奏）、HIGH=band6–7（镲/空气声）。
**这是代理**——军鼓鼓身会落进 MELODY，最终裁决靠听感。melody% = MELODY 类
master onset 的保留率；pairs% = 成对存活率。

## 结果（6 首均值）

| 难度 | 变体 | melody% | perc% | pairs% | 音符数 |
|---|---|---|---|---|---|
| EASY | base | 18.3 | 19.1 | **2.1** | 256 |
| EASY | 任何分池 | ~16.5 | ~21.6 | 0.0 | 255 |
| NORMAL | base | 41.7 | 40.6 | **14.3** | 567 |
| NORMAL | pool80（3 旋律+1 打击） | **49.3** | 22.7 | **20.1** | 519 |
| HARD | base | 75.5 | 75.4 | 57.0 | 1038 |
| HARD | pool80 | 78.0 | 23.3 | 61.7 | 748 |
| HARD | pool65 | 66.2 | 44.6 | 44.5 | 780 |

变体：norm = 强度按 voice 类内曲内 percentile 归一；poolX = 旋律/打击分池、
旋律份额 X；run65 = pool65 + 旋律连跑加分。完整逐曲表由脚本输出。

## 五个结论

1. **排序无关紧要**：norm 全场 +1pp 以内。瓶颈是预算与 min-gap，不是打分——
   "调阈值/调排序"救不了旋律。
2. **旋律优先分池在 NORMAL 有效**：pairs 14.3→20.1%、melody 41.7→49.3%，
   代价 perc 40.6→22.7%。HARD 全局预算本来就旋律友好（75%），分池反而伤
   （pool65 各项全降）；EASY 无操作空间（整数预算恒为 1+1）。
3. **min-gap 是 EASY 的旋律杀手**（300 ms 禁止任何连跑），结构上限 pairs≈0；
   想要 EASY 有旋律线，得允许旋律链豁免 min-gap 或按链成组。
4. **旋律链保护必须改准入**：run 加分零效果——1 s 窗口准入按时间序、不吃分数，
   加分改不了谁被裁。要保线，需按链成组进调度（同和弦处理）或改按分数准入。
5. **份额参数受整数化支配**：NPS 帮 cap 向下取整（2.6→2），share 0.5 与 0.65
   在 NORMAL 输出完全相同。暴露给用户的参数应是**名额**（旋律几/打击几）而非比例。

## 建议的参数面（呼应"手机上按曲风暴露参数"）

- 每难度**旋律/打击名额**（NORMAL 默认 3+1 即 pool80 等价；EASY 1+1；HARD 不分池）；
- **旋律链保护**（开关）：连跑旋律成组参与调度，直接提 pairs%；
- 旋律豁免 min-gap（可选，EASY 才有意义）。
- 实施顺序：先"名额 + 链保护"落 Kotlin 验证，再谈 UI 暴露；听感 A/B 是最终验收。
